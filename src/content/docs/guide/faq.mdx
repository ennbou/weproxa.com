## General

### What is WePROXA?
WePROXA is a native macOS and Windows HTTP/HTTPS proxy debugger. It lets you capture, inspect, modify, and replay network traffic from apps on your computer.

### What platforms does WePROXA support?
Starting with WePROXA 3.0.0, WePROXA supports **macOS 11.0+** (Big Sur and later) on Apple Silicon and Intel Macs, plus **Windows 10** and **Windows 11**. The Windows build is installed from the Microsoft Store.

### Is WePROXA free?
WePROXA offers a free tier with core features. Advanced features are available with a Pro license. See [Pricing](/pricing/) for details.

### What license details does WePROXA show?
When a Pro license is active, **Settings** → **License** shows the details returned when the key was validated: the **subscription** (product and variant), the **expiration** date and time (or a note when none is scheduled), the **customer email** on the license, the **activation usage** (seats used out of the limit, or an unlimited indicator), and when the license was **last validated**. Use **Revalidate** to refresh these details against the license server, or **Deactivate** to release the activation on this machine.

## Setup & Configuration

### Why does WePROXA need a certificate for HTTPS inspection?
To inspect HTTPS (encrypted) traffic, WePROXA needs a trusted local Certificate Authority. This is standard practice for proxy debugging tools. The certificate is generated locally and never leaves your machine. On macOS, see [Certificate Trust](/guide/guides/certificate-trust/). On Windows, see [Windows HTTPS Certificate Setup](/guide/guides/windows-https-certificate-setup/).

### How do I enable the system proxy?
Click the play button in the toolbar or press `⌘ P` on macOS / `Ctrl + P` on Windows. WePROXA configures the system proxy automatically when capture starts and restores the previous settings when capture stops or the app exits normally. The separate device button controls LAN access for remote capture.

### Does WePROXA work with all apps?
Most apps that respect macOS or Windows system proxy settings will work automatically. Some apps (like those using custom proxy configurations or certificate pinning) may need additional setup.

### Can I activate my license or open settings from a link?
Yes. WePROXA registers the `weproxa://` URL scheme. Opening a `weproxa://` link — for example from your browser after a purchase — can **activate a license key** or **jump straight to a Settings section** without hunting through the app. If activation from a link fails, WePROXA opens the **License** settings so you can see the error and retry. For example, `weproxa://settings/certificate` opens the CA Certificate settings. See [Deep Links](/guide/guides/settings/#deep-links) for every link format and section name.

## HTTPS & Security

### Is my data safe?
Yes. WePROXA runs entirely on your local machine. No traffic data is ever sent to external servers. The CA certificate and private key are stored locally in the app's data directory.

### Can WePROXA decrypt HTTPS traffic?
Yes, when the WePROXA CA certificate is trusted. This is a standard man-in-the-middle (MITM) technique used by all proxy debugging tools.

### What about certificate pinning?
Apps with certificate pinning will reject WePROXA's generated certificates. This is by design — it's a security feature of those apps.

## Troubleshooting

### I don't see any requests
1. Make sure the proxy is **running** (green indicator in toolbar)
2. Check that the **system proxy** is enabled
3. Try opening a website in a browser that uses system proxy settings, such as Safari on macOS or Edge/Chrome on Windows
4. If one app is missing while other apps still show up, see [Why does an app refuse the WePROXA certificate?](#why-does-an-app-refuse-the-weproxa-certificate)

### HTTPS requests show certificate errors
The WePROXA CA certificate may not be trusted. On macOS, see [Certificate Trust](/guide/guides/certificate-trust/). On Windows, see [Windows HTTPS Certificate Setup](/guide/guides/windows-https-certificate-setup/).

### Why does an app refuse the WePROXA certificate?
When SSL decryption is on for an app or a host, WePROXA shows the app its own certificate instead of the website's. If the device does not trust the WePROXA certificate, the app refuses to connect. WePROXA can't see anything the app sends, so the app's requests are missing from the list while other apps still show up.

The request list shows a failed entry for each refused connection. It has the app name, the host, and the label **Not decrypted: certificate rejected**.

To fix it, do one of these:

1. **Install and trust the WePROXA certificate on the device that runs the app.** Each simulator, emulator, phone, and tablet needs its own copy. See [iOS Simulator](/guide/guides/ios-simulator/), [Android Emulator](/guide/guides/android-emulator/), and [Remote Devices](/guide/guides/remote-devices/). If you regenerated the certificate, install the new one too.
2. **Turn off SSL decryption for that app or host** if you don't need to see its HTTPS traffic. The app then connects normally, and WePROXA shows the connection as a tunnel.

If the certificate is installed and trusted and the app still refuses it, the app probably uses certificate pinning. See [What about certificate pinning?](#what-about-certificate-pinning)

WePROXA counts a connection as rejected when the app says it doesn't trust the certificate, or when the app closes the connection right after receiving the certificate. iOS and macOS apps reject a certificate the second way. A connection that closes before WePROXA sent its certificate isn't counted. WePROXA also doesn't add an entry when the website's own certificate is the problem, for example when it is expired, self-signed, or issued for another name. WePROXA passes that problem on to the app on purpose, so the app refuses it just as it would without WePROXA.

An app that quits while it is still connecting closes the connection the same way, so you can also see this entry right after you close an app. If the app's other requests show up normally, it trusts the certificate and you can ignore the entry.

### The app is slow with many requests
WePROXA keeps up to 10,000 requests in memory. Use the **Clear** button in the toolbar to remove old requests, or use filters to focus on relevant traffic.
